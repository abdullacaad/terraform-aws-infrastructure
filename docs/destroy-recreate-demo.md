# Destroy & Recreate Demo

This is the deliverable that proves Infrastructure as Code: the same files
rebuild the same infrastructure from nothing.

## 1. Deploy

```bash
make deploy ENV=dev        # or: ./scripts/deploy.sh dev
terraform output web_public_ips
curl http://<web-ip>/         # "It works — provisioned by Terraform + Ansible"
```

## 2. Destroy

```bash
make destroy ENV=dev       # or: ./scripts/destroy.sh dev
terraform state list       # (empty — nothing left)
```

Check the AWS Console: VPC, subnets, EC2, security groups are gone.
Billing stops (except nothing — dev has no NAT).

## 3. Recreate — identical, from code alone

```bash
make recreate ENV=dev      # destroy + apply + ansible, in one command
# or: ./scripts/recreate.sh dev
curl http://<new-web-ip>/     # same page, new IP — infra is reproducible
```

## What to screenshot for a portfolio / interview

1. `terraform plan` output (what will be created)
2. `terraform apply` — "Apply complete! Resources: 12 added"
3. `curl` showing the Nginx page on the EC2 public IP
4. `terraform destroy` — "Destroy complete! Resources: 12 destroyed"
5. `terraform apply` again — same count, same resources

## Talking points

- "Manual console clicks don't scale and can't be reviewed. This is versioned, reviewable, repeatable."
- "Dev and prod are the same modules with different tfvars — one web server and no NAT in dev, two web servers and NAT in prod."
- "Ansible is the configuration layer: Terraform provisions, Ansible configures. The inventory is generated by Terraform, so there's no manual IP step."
